`cartwright design install <slug>` now also brings the self-hosted font folders the design imports. A design such as `brutalist`, `editorial-ink` or `meridian` imports its fonts from `@/app/fonts/<family>/font`, a folder outside `designs/<slug>/`, so installing it into a project that lacked the folder (a `--profile site` scaffold, for one) left a design that would not build. The command now reads the pack's imports and fetches each `app/fonts/<family>/` from the same template ref as the pack, and prints which font folders it added. A folder you already have is never overwritten, even with `--force`: when it matches the template it is reported as already present, and when it differs it is kept and the output says so. When your own folder lacks the module the design imports, it is still left alone and the output warns that the design won't build until you add it; when the template's copy can't be fetched but your folder already has every module the design imports, that is reported as already present rather than as a failure. An import path that leaves `app/fonts/<family>/`, such as `@/app/fonts/../../x` or `../../app/fonts/archivo/../../x`, is refused and named, never fetched. The imports are read with a small lexer rather than a text search, so an import that only appears in a comment, in another string, or after a regex or a template literal is read correctly. A symlink where a font folder would go is left alone rather than written through, and when `app/` or `app/fonts/` is itself a symlink or a file, nothing is written and the output names the folders to copy by hand. A design with no font imports installs exactly as before. Not covered: fonts a design loads in any other way than an import, such as a CSS `url()` to a file outside its folder.
